# L — 앱 안 교실 보정

- 상태: 구현됨
- 단계: Phase 1(단독 모드), 사용자 요청·결정(2026-11-16)
- 막는 위협: 전 위협 — 직접 막지 않고 R2·R3(새 기기가 교실 안)과 교실 안팎·건물 밖 판정을 켠다 (설계 §3, §4.4)
- 수집기·플랫폼: BLE 광고(Windows 수동 스캔, macOS 능동 스캔)와 와이파이 스캔. 이 노트북 한 대의 경계만 잰다

## 흔적

교실 보정값은 "교실 끝에 놓인 휴대폰이 이 노트북에서 얼마나 세게 잡히는가"다. 블루투스(`inside_boundary_dbm`)와
와이파이(`wifi_inside_boundary_dbm`)를 따로 둔다 — 와이파이는 송신 출력·대역·안테나가 달라 같은 자리에서도 세기 척도가
다르다. 경계가 없으면 R2·R3과 교실 안팎 판정을 하지 않고 "보정 필요"를 알린다(AGENTS.md §2 규칙 4). 설계 §4.4는 운영 전
교실마다 기준 폰의 RSSI를 재서 경계를 저장하라고 한다.

## 조건

감독관이 자기 휴대폰(블루투스와 개인 핫스팟을 켬)으로 잰다. 시간은 백엔드의 세션 시각(ms)이다.

| 단계 | 조건 | 비고 |
|---|---|---|
| 목록 | 최근 `LIST_WINDOW_MS`(20초) 안에 본 BLE 기기와 와이파이를 각각 최근 `RECENT_SAMPLES`(5)개의 아래쪽 중앙값으로 센 순 정렬, 각 `LIST_LIMIT`(30)개 | 동점은 목록 번호 순. 이름: BLE 광고 이름 → 제조사 → "이름 없는 블루투스 기기", 와이파이 SSID → "이름을 숨긴 와이파이" |
| 고르기 | 감독관이 블루투스 하나와 와이파이 하나를 고른다(둘 다 필수). 고른 기기는 최근 `LIST_WINDOW_MS` 안에 보였어야 한다 | 고를 때 세기(최근 중앙값)를 기준값으로 둔다. 휴대폰은 노트북 가까이 둔 채 고르도록 안내 |
| 교실 끝 | 휴대폰을 교실 끝에 두고 `FAR_MS`(20초) 이상, 두 무선 모두 표본 `MIN_SAMPLES`(3)개 이상 | 와이파이는 스캔 간격(약 8초) 때문에 더 걸린다 |
| 못 찾음 | 교실 끝 단계가 `FAR_TIMEOUT_MS`(60초)가 지나도 어느 쪽이든 표본이 모자라면 실패(모자란 무선 종류를 알림) | |
| 경계 | 무선 종류마다 교실 끝 표본의 아래쪽 중앙값 | |
| 확인 | 고를 때 세기 − 경계가 `MIN_SEPARATION_DB`(10dB) **미만**이면 실패(그 무선 종류를 알림) | 상대 비교. 1–2m만 옮긴 측정을 막는다 |

고정 dBm 판정 상수는 없다. 비교는 같은 기기의 고를 때·교실 끝 값 사이의 차이뿐이다. 와이파이 경계가 없는 설정(예: 설치
담당자가 블루투스 경계만 적은 설정)은 블루투스 경계를 빌리지 않고 와이파이의 경계 판정(R3, 교실 안팎)을 미루며 "와이파이 기준값 없음" 주의를 보인다 — 출력이 센 와이파이에 블루투스 경계를 쓰면 옆 교실 AP까지 교실 안이 된다.

## 언제, 어디서 재나

- **처음 설정 바로 뒤.** 교실과 노트북 자리를 고르면 감지보다 보정을 먼저 한다(사용자 요청 2026-11-16). 그만두면 보정
  없이 감지를 시작하고 "보정 필요" 주의를 보인다. 자리를 다시 고르면(처음 설정 다시 하기) 보정도 다시 한다.
- **휴대폰을 둘 자리 추천: 노트북에서 가장 먼 구석.** 노트북 자리는 칠판을 남쪽에 둔 5×5 칸에서 고른다. 경계는 "교실 끝
  휴대폰이 얼마나 세게 잡히나"이므로 교실 안에서 가장 먼 곳에서 재야 교실 안 기기가 모두 경계 안에 든다. 줄과 칸마다 반대쪽
  끝을 고르고, 가운데 줄·칸이면 두 끝이 똑같이 멀어 뒤쪽(북)·서쪽 끝으로 정한다(칠판 쪽은 감독관 책상과 사람이 많아 차폐가
  생기기 쉽다). 판정이 아니라 안내라서 화면 쪽(`desktop/src/backend.js`의 `calibrationSpot`)에 두고 `desktop/test/backend.test.js`로
  시험한다.
- 추천은 격자 거리만 본다. 벽 재질, 문, 기둥, 교실 모양(긴 교실)은 모른다 — 미검증 항목과 같다.

## 쓰는 필드

BLE: 주소(또는 macOS 호스트별 UUID), RSSI, 첫 제조사 ID, **광고 이름**(AGENTS.md §3.2 — 이 목록에만). 와이파이: BSSID, SSID,
대역, RSSI. 목록과 표본은 보정 프로세스 메모리에만 있고, 끝나면 경계 정수 두 개만 앱 설정에 남긴다. 화면으로는 식별자 대신
보정 안에서만 쓰는 번호("b3", "w1")를 보낸다(AGENTS.md §3.3).

## 가중치

없음. 경계는 R2(블루투스)·R3(와이파이) 조건과 위치 판정이 쓴다(`docs/rules/R2-new-ble-in-room.md`, `R3-new-wifi-in-room.md`,
`L-room-locator.md`).

## 오탐 요인

| 요인 | 반응 | 걸러내는 것 |
|---|---|---|
| 감독관이 남의 기기를 고름 | 엉뚱한 기기로 잰 경계 | 목록은 센 순이라 노트북에 댄 휴대폰이 맨 위("가장 가까움"), 이름이 보이면 이름으로 확인 |
| 교실 끝에서 사람이 휴대폰을 쥐고 있음 | 경계가 낮아짐(차폐) → 복도·옆 교실 기기까지 "교실 안"에 들고, 건물 밖 감점 기준도 함께 내려가 사실상 꺼짐(오탐 증가) | 안내 문구: 휴대폰을 책상에 두고 떨어지기 |
| 가장 먼 구석이 복도·옆 교실 벽과 붙음 | 벽 감쇠까지 담겨 경계가 낮아짐 → 벽 너머 복도·옆 교실 기기가 "교실 안", 건물 밖 감점도 함께 내려감(오탐 증가) | 안내 문구: 구석이라도 벽에 바짝 붙이지 말고 한 걸음 안쪽 책상 위. 실측 전까지 미검증 |
| 교실 끝이 아닌 가까운 자리에 둠 | 경계가 높아짐 → 노트북 몇 걸음 밖의 새 기기를 교실 밖으로 봄(R2·R3 미탐) | `MIN_SEPARATION_DB` 미만이면 실패 |
| 고를 때 휴대폰이 이미 멀리 있음 | 기준값이 낮아 `MIN_SEPARATION_DB` 확인이 실패할 수 있음 | 실패 문구로 "고를 때는 노트북 가까이" 안내 |
| 보정 중·직후 감지 다시 시작 | 기준선을 새로 익히는 동안 켜져 있던 기기가 "원래 있던 기기"로 굳음 | 감지 중에 보정을 시작하면 확인 창(시험 중에는 누르지 말 것) |
| 측정 중 블루투스 주소 교체 | 교실 끝 표본이 모이지 않음 | 시간 초과로 실패, 다시 고르기 |
| macOS 서명 없는 앱 | 와이파이 이름·주소를 받지 못해 와이파이 목록이 빔 | 화면에 와이파이 문제(위치 권한)를 보이고 위치 설정 바로 가기. 둘 다 필수라 보정은 못 한다 |

## 경계

고를 때 − 경계가 정확히 `MIN_SEPARATION_DB`면 통과. 정확히 `LIST_WINDOW_MS` 전에 본 기기는 목록에 있다. 표본이 짝수 개면
아래쪽 중앙값. 와이파이 번호를 블루투스 자리에 보내면 고르지 않은 것으로 본다.
