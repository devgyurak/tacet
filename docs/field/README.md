# 실측 기록

교실 보정, 위치 판정 신뢰도 기준, 기기 특성(안경·폰 광고, Wi-Fi Direct), 플랫폼 동작(macOS
CoreWLAN 버전별)을 확인한 실측의 **요약**을 이 디렉터리에 둔다. 파일 이름은
`<YYYY-MM-DD>-<영어-케밥>.md`다. 절차는 `field-test` 스킬에 있다.

## 지킬 것

- **요약 수치만.** 캡처, IQ 녹음, 스캔 원본은 측정한 컴퓨터에만 두고 기록 뒤에 지운다. 저장소에 올리지 않는다(AGENTS.md §3.3).
- **식별 정보 없음.** MAC, SSID, 기기 이름, 사람, 학교·교실을 특정할 정보 대신 라벨을 쓴다: "폰 A(안드로이드, 6GHz 핫스팟)",
  "교실 X(약 9m × 7m, 철근 콘크리트)".
- **우리 기기만.** 측정 대상은 실측하는 사람이 소유하거나 빌린 기기다. 주변의 다른 기기는 결과에 남기지 않는다.
- **송신은 기기의 정상 기능으로 사람이 켠다.** 우리 도구와 에이전트는 송신하지 않는다(AGENTS.md §3.1).
- **교실 보정값은 설정 파일이 정본이다.** 이 기록은 그 값을 어떻게 얻었는지의 근거이고, 실제 교실을 특정할 이름은
  쓰지 않는다.
- **실제 시험 중 측정이 아니다.** 빈 교실·실험 공간에서 한다(설계 §8).

## 템플릿

```markdown
# <날짜> — <질문 한 줄>

- 확인할 항목: `TODO(field-unverified)` 위치, 관련 규칙·플랫폼 노트
- 측정자: (역할만, 예: 개발자 1명)

## 질문

한 문장. 예: "철근 콘크리트 벽 하나 너머 옆 교실 폰의 BLE RSSI 중앙값이 우리 교실 뒤 센서보다 몇 dB 낮은가?"

## 조건

| 항목 | 값 |
|---|---|
| 장소 | 교실 X(크기, 벽 재질, 층) |
| 기기 | 폰 A(기종 분류, 설정), 안경 B |
| 수집 | 수집기, OS·버전, 어댑터·칩 |
| 배치 | 거리·위치 격자 |
| 반복 | 위치마다 N회 |

## 판정 기준

어떤 결과면 무엇을 어떻게 정할지 측정 전에 적는다.

## 결과

| 위치 | 거리·차폐 | RSSI 중앙값 | 범위 | 반복 | 탐지율 | 첫 관측까지 | 적중 규칙 |
|---|---|---|---|---|---|---|---|

## 결론과 한계

결론, 표본 수, 한 건물·한 기종 같은 한계, 다음에 확인할 것.

## 반영

갱신한 노트, 해소한 `TODO(field-unverified)`, 연 `decision` 이슈.
```
