현재 단계는 `▶`로 시작하는 한 줄이다. SessionStart 훅이 그것을 알리고, `scripts/check_agent_config.py`는
정확히 하나가 아니면 실패한다. 표식은 그 단계의 완료 기준(설계 §9)을 채웠을 때만 옮긴다 — 사람이 정한다.

▶ Phase 0 — 작업 공간·CI·에이전트 워크플로 (macOS에서 게이트 통과, Windows·Linux CI 확인 대기)

사용자 요청(2026-11-16, "끝까지 만들어 달라")으로 이후 단계의 코드도 먼저 만들었다. 단계 표식은 완료 기준의 실측·CI 확인이
끝날 때 사람이 옮긴다. 코드로 할 수 있는 것과 사람·장비·결정이 필요한 것을 나눠 적는다.

      영어. 번역본 없음. (AGENTS.md §9)
- [x] **하네스: Claude Code와 Codex.** 정본은 루트 `AGENTS.md` 하나. (`.agents/README.md`)
- [x] **배포 대상은 Windows 11과 macOS, 리눅스는 개발·검증용.** (설계 §2, AGENTS.md §2)
- [x] **블루투스 연결 탐지를 다루지 않는다 (사용자 결정, 2026-11-16).** 전용 스니퍼 장비로 블루투스 연결 패킷을 잡던
      규칙 R8·R9와 그 수집기·선택 기능·장비 확인·비교 도구를 코드와 문서에서 걷어 냈다. 광고 없이 연결만 유지하는
      기기(설계 §3의 T6·T7)는 범위 밖이다. R8·R9 ID는 다시 쓰지 않는다. (설계 §4.6) 예외 기기 목록(`whitelist.toml`)의
      `Lap`·`AccessAddr` 항목은 이제 형식 오류로 시작을 막는다 — 지우고, BLE 기기면 `Mac`이나 `Manufacturer`로 옮긴다.
- [x] **화면: Electron (사용자 요청, 2026-11-16).** egui 화면을 걷어 내고 `desktop/`의 Electron으로 바꿨다. Rust
      `tacet`는 화면 없는 백엔드가 되어 표준 입출력 JSON으로 화면과 이야기한다(네트워크 포트 없음). 런타임 npm 의존성은
      없고(Electron 자체만), 빌드 도구는 electron-builder다. 웹 대시보드도 같은 화면 파일을 쓴다. npm 의존성의 라이선스는
      `cargo deny`가 보지 않는다 — 열린 결정 참고.
- [x] **감독관 기본 흐름 (사용자 요청, 2026-11-16).** 처음 켜면 교실 이름과 노트북 자리(칠판을 남쪽에 둔 교실 그림에서
      앞·뒤 × 서·가운데·동)를 고르고 이 노트북 혼자 감지한다(단독 모드). 판정에는 앞·뒤만 쓰고 서·동은 표시용이다. 서버·센서·
      본부 화면 보기는 개발자 모드(Ctrl/⌘+Shift+D)에서 설정 파일을 골라 쓴다 — "단순 감지에 집중".
- [x] **쉬운 말 안내.** 감독관 화면의 문구는 core `explain`이 만든다: 알림은 무엇·어디·확실도·왜·할 일, 문제 안내는
      어디서·무엇이·영향·할 일. 규칙 ID·dBm·식별자는 개발자 모드에서만 보인다. 무엇을 감독관에게 보일지는 core가 정한
      무게(문제·주의·참고)로 고른다. 제조사 ID만으로 기기 종류를 단정하지 않는다("휴대폰일 수 있는").
- [x] **기술 정보는 개발자 모드에서만.** 데스크톱은 개발자 모드가 아니면 메인 프로세스가 기술 정보(규칙 ID, 신호 세기,
      BSSID 등 식별자, 서버 정보, 알림 기록)를 빼고 화면에 넘긴다. 개발자 모드는 저장하지 않는다(실행마다 다시 켬).
      웹 대시보드는 여러 기기가 보므로 언제나 기술 정보를 뺀 화면만 보낸다(`BuildingView::without_technical`).
- [x] **앱 안 교실 보정 (사용자 요청·결정, 2026-11-16).** 지금 잡히는 블루투스 기기·와이파이 목록에서 감독관이 자기

      저장한다(`docs/rules/L-room-calibration.md`, `core::calibrate`, `tacet calibrate`). 목록에 쓰려고 BLE 광고 이름을 받는다
      (AGENTS.md §3.2, 저장하지 않음). 시간·표본 수·간격 기준은 미검증이다.
- [x] **무선 종류별 경계.** `inside_boundary_dbm`(블루투스)과 `wifi_inside_boundary_dbm`(와이파이)을 따로 둔다.

## 알려진 차이

- 설계 §4.7의 알림 예시(-58/-66/-71dBm → "신뢰도 중")는 같은 절의 기준(1·2위 차이 13dB → 높음)과 맞지 않는다. 구현은
  기준을 따른다. 실측 보정 때 다시 본다(`docs/rules/L-room-locator.md`).
- 알림 문구(개발자 모드)는 BSSID 등 식별자를 **전체** 보여 준다 — 표시 범위는 아래 열린 결정이다. 화면·대시보드에만 보이고 저장(세션 보고서)에는 해시만 남는다.
- Windows 코드(WinRT BLE, WLAN API, 절전 방지)는 macOS에서 교차 컴파일 검사만 했다. 앱 전체(ring의 C 코드 포함)의
  Windows 빌드는 CI의 Windows 작업이 처음 확인한다.

## 열린 결정

사람이 정하고 `decision` 라벨 GitHub 이슈(`.github/ISSUE_TEMPLATE/decision.md`)로 남긴다.

- [ ] **감독관 화면의 식별자 표시 범위** — 지금은 전체 표시. 일부만(예: 뒤 2바이트) 보일지, 대시보드·본부 화면으로
      내보낼 범위를 줄일지.
- [ ] **Windows 서버 키 보호** — 유닉스는 0600 파일. Windows는 사용자 프로필 폴더 권한에 기대고 있다. DPAPI로
      감쌀지.
- [ ] **탐지 모델의 남은 질문(검토에서 나옴)** — 여러 흔적을 한 기기로 묶을지(폰 BLE + 핫스팟), 센서마다 다른 경계를
      정규화해 교실 순위를 매길지. 실측 뒤 정한다.
- [ ] **송신 예외의 법적 해석** — macOS BLE 능동 스캔 요청과 OS Wi-Fi 스캔 probe request. 법률 검토 대상.
- [ ] **n78 시간 게이팅(설계 §4.5 (A))** — 법률 검토 전 착수하지 않는다.
- [ ] **기본 가중치·신뢰도 기준** — R1–R7 정수 가중치, 알림 문턱(4/6/10), 신뢰도 기준(10/5dB). 실측 뒤에 정한다.
- [ ] **대시보드 HTTPS** — 지금은 내부망 **평문 HTTP** + 접속 코드. 같은 망의 다른 기기가 패킷을 보면 접속 코드와
      세션 쿠키(`Secure` 없음)를 얻어 감독관 화면을 볼 수 있다 — 유선 내부망 전제다. 세션 토큰은 세션이 끝날 때까지
      유효하다. 태블릿 브라우저의 자체 서명 인증서 경고와 맞바꾸는 문제.
- [ ] **npm 의존성 라이선스 검사** — `deny.toml`은 Rust만 본다. 배포물에 들어가는 것은 Electron(MIT, Chromium 등
      포함)뿐이고 electron-builder는 빌드 도구다. 의존성을 더할 때 라이선스 검사 도구를 들일지.
- [ ] **감독관이 직접 예외 기기를 등록하는 화면** — 지금은 설치 담당자가 파일로 적는다. 시험 당일 신고된 기기를 감독관이
      바로 등록할 수 있어야 하는지, 그때 잘못 등록해 탐지를 끄는 위험을 어떻게 막을지.
- [ ] **센서 신원** — 센서 코드 하나를 모든 센서가 같이 쓰므로, 코드를 가진 기기는 다른 센서 ID로 붙어 그 센서의
      연결을 대신할 수 있다. 센서별 코드나 인증서를 둘지.
- [ ] **센서 프로토콜 버전 정책과 보고서 보존 기간** — 지금은 버전 1, 보고서는 사용자가 저장할 때만(해시만).
- [ ] **설계 §10의 나머지** — Windows 10 지원, 서명 인증서·Apple 계정,
      의료기기·보청기 화이트리스트 절차, 수거폰 운영 절차, 센서망 구성, 지향성 안테나.
