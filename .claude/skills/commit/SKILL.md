# 커밋 · PR · 브랜치 이름

> 커밋은 사용자가 요청할 때만 한다. 이 스킬은 "언제"가 아니라 "어떻게"다.

커밋 제목, PR 제목, 브랜치는 **같은 접두사 하나**를 쓴다. PR 하나는 변경 한 종류 — **규칙 하나, 수집기
하나, 실행 모드 하나, 또는 버그 하나** — 만 담으므로 접두사도 하나다.

```
<접두사>: <요약>

<본문 — "왜">
```

접두사는 영어, 요약·본문·PR·이슈 글은 **한국어**다(AGENTS.md §9).

## 1. 먼저 바뀐 것을 본다

접두사는 기억이 아니라 diff로 정한다.

```bash
git status --short
git diff --stat
git diff            # 스테이지 전
git diff --staged   # 스테이지 후
```

## 2. 접두사 하나를 고른다

| 접두사 | 언제 | 예 |
| --- | --- | --- |
| `ADD:` | 새것 — 탐지 규칙 · 수집기 · 실행 모드 · 기능 · 테스트 · 워크플로 · 의존성 | `ADD: R1a 스마트 안경 제조사 ID 탐지` |
| `FIX:` | 버그 — 오탐·미탐·위치 오판 포함, 동작이 노트와 달랐다 | `FIX: 짝수 개 RSSI 중앙값을 아래쪽으로` |
| `REF:` | 구조만 — **관찰 가능한 동작은 그대로** | `REF: 규칙 엔진을 모듈로 나눔` |
| `DEL:` | 제거 — 기능 · 파일 · 죽은 코드 | `DEL: 쓰지 않는 iw 출력 파서` |
| `DOCS:` | 문서만 | `DOCS: 옆 교실 RSSI 실측 기록` |
| `UPT:` | 의존성 **버전 올리기** | `UPT: btleplug 0.12` |

대문자, 콜론, 공백 하나. `Add:`나 `ADD :`가 아니다.

### 경계가 애매할 때

**1. 관찰 가능한 동작이 바뀌었나?** 테스트, 스냅숏, 알림, 위치 판정, 보고서 중 무엇이라도 달라지는가?
- 아니다 → `REF:`.
- 새 동작 → `ADD:`.
- 틀린 동작을 바로잡음 → `FIX:` (고치기 전에 실패하던 테스트와 함께).

**2. 의존성 추가 vs 올리기.** `Cargo.toml`에 새 크레이트 → `ADD:`. 버전만 올렸거나 `Cargo.lock`만 → `UPT:`.

**3. 문서와 코드를 함께 바꾸면 `DOCS:`가 아니다.** 코드와 그 규칙 노트를 함께 바꾸면 코드의 접두사를 쓴다.

**3-1. 문서는 새로 더해도 `DOCS:`다.** 규칙 노트, 플랫폼 노트, 실측·보정 기록만 더하면 `DOCS:`. 에이전트 설정도
문서다 — `.claude/` · `.agents/` · `.codex/` 아래 전부.

**하지만 `scripts/`는 코드다** — 실행된다. 훅이나 게이트 변경은 `ADD:`/`FIX:`. `.github/workflows/`도 코드다.

**4. 테스트만 → `ADD:`.** 기존 테스트의 구조만 정리하면 `REF:`.

**5. 접두사 두 개가 맞으면 → 커밋을 나눈다.**

## 3. 제목

- 한국어, 명사구나 "~함/~로 바꿈" 꼴, 마침표 없음.
- 접두사 포함 50자 안팎.
- 파일 목록이 아니라 **동작**을 쓴다. 실측 장소·사람·기기 식별 정보(MAC, SSID)를 쓰지 않는다.

```
좋음:  FIX: 수거폰 보관 위치의 신호를 감점
나쁨:  FIX: score.rs
나쁨:  FIX: 3층 2반 김OO 폰 오탐
```

## 4. 본문 — **왜**

**무엇**은 diff에 있다. 오탐 방지 예외는 이유가 남지 않으면 다음 사람이 "정리"해서 회귀를 만든다.

```
FIX: 짝수 개 RSSI 중앙값을 아래쪽으로

위치 판정 노트(docs/rules/L-room-locator.md)는 표본이 짝수 개면 아래쪽 값을
중앙값으로 정하는데 코드는 두 값의 평균을 내서 정수 반올림이 실행마다 달라질
수 있었다. given_even_rssi_samples_when_median_taken_then_lower_middle_is_used가
이제 통과한다.
```

본문이 **필수**인 경우: 수집기·센서 프로토콜·알림 문구·보존 정책·라이선스 등 AGENTS.md §3에 닿는 변경, `unsafe`를
쓰는 변경, 스냅숏이나 기본 가중치·신뢰도 기준을 바꾸는 변경.

## 5. 브랜치 이름

`<소문자 접두사>/<영어-케밥>`, `develop`에서 따고 PR은 `develop`으로(`main`은 릴리스 전용).

```
add/r1a-glasses-vendor
fix/median-even-count
docs/field-room-calibration
```

## 6. PR 본문

`.github/pull_request_template.md`를 쓴다. 반드시 적을 것:

- **탐지** — 규칙·수집기·모드·버그와 그 노트(`docs/rules/`, `docs/platform/`).
- **위협·오탐·위치** — 영향받는 위협(T1–T7), 오탐 요인, 교실 배정, `detection-reviewer` 결과.
- **테스트** — 고정하는 테스트, 새 테스트가 먼저 실패했다는 것.
- **스냅숏** — 더하거나 바꾼 스냅숏과 **새 결과가 맞는 이유**. "스냅숏 갱신"만으로는 이유가 아니다.
- **법·개인정보·라이선스** — 송신·디코딩·보존·내부망·문구·의존성 라이선스에 닿는지, `compliance-auditor` 결과.
- **미검증** — 더한 `TODO(field-unverified)`와 확인 방법.
- **결정 · 단계** — 근거한 `decision` 이슈(`#N에서 결정`), 이 변경의 단계.

## 7. 라벨

릴리스 노트는 main의 `vX.Y.Z` 태그에서 이 라벨로 묶어 자동 생성한다(`.github/release.yml`). 노트에서 빼려면 `skip-changelog`.

| 접두사 | 라벨 | 릴리스 노트 |
| --- | --- | --- |
| `ADD:` | `feature` — 테스트만이면 `test`, 워크플로·게이트만이면 `ci`, 새 의존성이면 `dependencies` | ✨ (예외는 🧹 / 📦) |
| `FIX:` | `bug` | 🐛 버그 수정 |
| `REF:` | `refactor` (CI·테스트만이면 `ci` / `test`) | 🧹 내부 |
| `DEL:` | `refactor` | 🧹 내부 |
| `DOCS:` | `documentation` | 📝 문서 |
| `UPT:` | `dependencies` | 📦 의존성 |

## 8. 커밋 전 체크리스트

- [ ] 접두사가 diff와 맞는가? (동작이 바뀌었는데 `REF:`면 틀렸다)
- [ ] PR 하나에 규칙·수집기·모드·버그 하나인가?
- [ ] 제목이 **동작**을 말하는가?
- [ ] 놀라운 것에 **왜**가 남아 있는가?
- [ ] `./scripts/verify.sh`가 통과했는가? (`verify` 스킬)
- [ ] 스냅숏 변경마다 PR에 이유가 있는가?
- [ ] 송신 코드, 디코딩, 실제 MAC·SSID·캡처·녹화, 내부망 밖 전송, 단정 문구, 서명 키가 없는가? (`compliance-auditor`)
- [ ] 모두 한국어인가? (접두사·식별자 제외)
